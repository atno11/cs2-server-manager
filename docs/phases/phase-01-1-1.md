## Investigation and reproduction

LC-R01 was reproduced before the fix: `go test -run '^TestCompletedProcessStopDoesNotMutateState$' -count=1 ./internal/manager` exited 1 because `terminate` accepted an already completed process. The same test passes after the ownership guard. LC-R02 was confirmed by static inspection: `cmd.Wait` reaped the leader before `kill(-pgid, SIGKILL)`, leaving a potential group-ID reuse window. The old code also discarded `Manager.Close` and `Server.Shutdown` errors. The published `Restart` stopped on a confirmed forced outcome. Natural descendant exit previously escalated immediately. Those findings were validated with targeted behavioral tests after implementation; no pre-fix test failure was captured for them.

The original 20 top-level tests remain. `Close` now returns the same joined error to every concurrent caller. The HTTP server returns shutdown and manager cleanup errors, and calls `Server.Close` after a graceful shutdown deadline to close active connections. `Restart` may replace a process after a confirmed forced stop only when group cleanup and signal delivery succeeded; `LastTermination` preserves the forced-stop diagnostic. Cleanup failure or a completion timeout retains `entry.proc` and blocks replacement. A Stop request that loses a race to successful natural completion returns success without sending another signal or changing state.

## Ownership and bounds

Linux `SysProcAttr.PidFD` and `pidfd_send_signal` with `PIDFD_SIGNAL_PROCESS_GROUP` target the process group through a stable process reference. The manager requires this capability and fails launch when it is unavailable; the group flag requires Linux 6.9 or newer. `waitid(WEXITED|WNOWAIT)` observes leader exit without reaping it. The leader stays waitable while descendants receive SIGTERM, up to two seconds to exit, then SIGKILL and up to two more seconds. Only then does `cmd.Wait` reap the leader. Group membership is inspected through `/proc`; an unreadable entry makes cleanup fail closed and retains ownership. The scan is bounded by the same deadlines when membership is readable. Stop and Close share that supervision and do not signal after completion is observed. A timed-out or failed cleanup remains visible as `failed`, with ownership retained to prevent replacement.

This design removes the prior stale negative-PGID signal path. It does not supervise descendants that detach or leave the group, nor can it recover processes after abrupt manager death. An uninterruptible process can outlive the bounded wait; ownership is retained and replacement is blocked. `/proc` visibility is required for positive group cleanup confirmation. The raw pidfd syscall number is used for the supported Linux target; portability to other operating systems or older kernels is not claimed. These are simulated fake-process results, not native CS2 validation.

Authoritative references: [Linux waitid/WNOWAIT](https://man7.org/linux/man-pages/man2/waitid.2.html), [Linux pidfd_send_signal and process-group flag](https://man7.org/linux/man-pages/man2/pidfd_send_signal.2.html), [Go HTTP Shutdown contract](https://pkg.go.dev/net/http#Server.Shutdown).
