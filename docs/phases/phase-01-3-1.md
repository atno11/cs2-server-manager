## Review findings and pre-fix reproduction

DB-R01 is confirmed. The original `Open` configured the pooled connection after `Ping`; `SetMaxOpenConns(1)` did not pin that physical connection. Running the new replacement test on an isolated `b83bd2b` snapshot failed with `temp_store="0" want "2"` on one run and `foreign_keys="0" want "1"` on another (map iteration changes which setting is reported first). The v1.63.0 driver's DSN `_pragma` implementation applies values in `newConn` on every physical connection; no global hook is needed. DELETE journal mode is stored in the database file, while busy timeout, synchronous, foreign keys and temp store are connection settings that need initialization on each connection. Startup still reads back all five effective values.

DB-R02 is confirmed. The isolated baseline accepted version 1 schemas with missing columns, missing uniqueness, incompatible type, absent ID check, an extra foreign key, an extra trigger, and an extra index. Its table-name check did not establish compatibility; `quick_check` checks integrity, not this application contract. Startup now checks exact visible columns and types, nullability, primary keys, expected unique indexes, foreign keys, allowed schema objects, migration rows and constraint behavior. Constraint probes execute in a transaction that is rolled back and require actual SQLite constraint errors. Incompatible databases fail explicitly; no repair or JSON fallback is attempted. The threat model excludes hostile concurrent external database changes.

DB-R03 is confirmed. SQLite `length(TEXT)` counts characters, while the 16 KiB stored argument limit is in bytes. The isolated baseline accepted the new oversized UTF-8 fixture. `Load` now checks `length(CAST(value AS BLOB))` for all bounded text fields, rejects invalid SQLite storage types, limits the result query to 33 rows, and retains the 32-definition cap. JSON decoding still rejects malformed argument representations, and the manager applies its existing definition and policy validation after loading. The loading check allocates no oversized Go field before the SQL aggregate rejects it.

DB-R04 did not reveal a driver transaction cleanup defect. Source inspection of v1.63.0 `tx.Commit` shows that after an unsuccessful commit it checks SQLite autocommit state and rolls back an active transaction; `database/sql` also rolls back a transaction whose context is canceled. A real reader transaction held a SHARED lock while a writer inserted successfully and then failed at `Commit`; no row remained, the connection was usable, and a `Store.Put` retry succeeded after releasing the reader. A canceled transaction likewise left no row and released the connection. The failed-commit test passed on the isolated baseline, so no speculative recovery path or blind write retry was added. Existing manager persistence-failure tests retain in-memory registration/removal consistency. A process crash or hostile external database writer remains outside the supported runtime model.

The isolated pre-fix regression command was `GOCACHE=/tmp/cs2m-phase131-cache GOTMPDIR=/tmp go test -count=1 -run 'TestConnectionSettingsAfterReplacement|TestVersionOneSchemaCompatibility|TestLoadRejectsOversizedUTF8AndInvalidTypes|TestFailedCommitRollsBackAndConnectionRecovers' ./internal/storage`; exit 1. It reported replacement connection settings, seven incompatible-schema subcases and oversized stored data as failures. The failed-commit test passed. Invalid migration metadata was rejected by the existing SQLite `CHECK` during fixture construction; the final fixture uses `PRAGMA ignore_check_constraints` to store deliberately corrupt metadata before testing startup rejection.

## Validation and limitations

The driver remains `modernc.org/sqlite v1.63.0`; no dependency or schema version change was needed. References reviewed: [versioned driver documentation](https://pkg.go.dev/modernc.org/sqlite@v1.63.0), [SQLite PRAGMAs](https://www.sqlite.org/pragma.html), and [SQLite `length` byte and character behavior](https://www.sqlite.org/lang_corefunc.html). The tests use temporary real SQLite files, a controlled secondary reader connection, and explicit context cancellation. No native CS2 binary was used; native CS2 validation remains PENDING. SQLite schema checks are deliberately scoped to the version 1 application contract. External writers changing schema or rows while this manager owns its runtime directory remain unsupported.

Final validation on the completed working tree: `go mod verify` exit 0 (`all modules verified`); `GOCACHE=/tmp/cs2m-phase131-cache GOTMPDIR=/tmp go test -race -count=3 -timeout=180s ./...` exit 0 for cmd, manager, security and storage; `bash scripts/check.sh` exit 0 with PASS for gofmt, vet, uncached tests, race, coverage, build and Git diff check. The final check reported cmd 68.8%, manager 82.0%, security 74.4%, storage 80.7%, and total 79.8% coverage, a 0.4 percentage-point increase from the isolated 79.4% baseline. `rg '^func Test' cmd internal | wc -l` counted 87 top-level tests versus 81 at baseline. These checks use simulated fixtures and real temporary SQLite databases; native CS2 validation remains PENDING.
